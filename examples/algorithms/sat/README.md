# DPLL SAT ソルバーと Mac CPU 比較

CNF-SAT を Bend と C で実装した。単位伝播、決定、逐次バックトラックを行い、
SAT では充足する割当を返す。各変数を正負の U32 ビットマスクで表すため、対応範囲は
**0〜32変数、最大4096節**。CDCL、学習節、watched literals、再スタートは実装していない。

```sh
just check-sat

# SAT。返されたモデルは元の CNF に照合する
just sat examples/algorithms/sat/backtrack-sat.cnf
# s SATISFIABLE
# v -1 -2 3 0

# 同じファイルを C 版でも解く
just sat examples/algorithms/sat/backtrack-sat.cnf --backend c

# 一つの CNF の先頭4変数を16通りに分ける。6羽/5巣箱は UNSAT
just sat examples/algorithms/sat/pigeonhole-6-5.cnf --split-depth 4 --threads 10

# 独立した CNF のバッチ。生成とモデル検証も計測に含む
just bench-algorithms sat --output build/sat/batch.json

# 一つの CNF を逐次に2048回解き、分割の深さを変える
just bench-sat examples/algorithms/sat/pigeonhole-6-5.cnf --output build/sat/partition.json
```

CLI は DIMACS の `p cnf <変数数> <節数>`、`c` コメント、0終端の節を読む。
複数行の節、空の CNF、空の節、重複するリテラル、恒真節に対応する。
ヘッダ、節数、終端、変数の範囲が不正な入力はコンパイル前に拒否する。
入力ファイルごとに定数を持つネイティブバイナリを生成するので、CLI の所要時間にはコンパイルも入る。
速度比較の時間は生成済みのバイナリだけを実行したもので、DIMACS の読込・コンパイルを含めない。

ソルバーの実装は [sat-core.bend](../sat-core.bend) と [sat-core.h](../sat-core.h)。
節の順に調べ、最初の単位節を伝播する。単位節がなくなると、最初の未充足節の
未割当変数のうち番号が最小の変数を選び、true 側を先に試す。
その枝で SAT が見つかれば false 側は評価しない。
未使用の変数は false で補い、完全なモデルとして出力する。

再帰と単位伝播の fuel はどちらも33で、1経路上の32変数と最後の判定を覆う。
これは探索ノードの予算ではない。fuel 切れは `Unknown` にし、UNSAT にはしない。
探索ノード数の U32 集計は 2^32 を法とする。

独立バッチでは、CNF ごとに生成・探索・検証を済ませ、上位の fork で仕事を配る。
入力は固定した xorshift32 の種から生成する、植え込んだ解のないランダム3-SAT。
各節は異なる3変数を含み、節数は `floor(4.25 × 変数数)`。
小さいバッチにも SAT / UNSAT の両方が含まれることを総当たりで確認した。
出力の checksum は `(モデル + 2654435761) × (入力番号 + 1)` の SAT 件の和、
detail は全 CNF の探索ノード数。モデル不成立や `Unknown` は errors に数える。

単一 CNF の分割は、先頭 `depth` 変数の全初期割当を独立に解く。
`depth=0` は通常の逐次 DPLL。指定範囲は `0..min(12, 変数数)`。
分割後は、各部分探索で最初の解が見つかるとその枝を打ち切るが、全初期割当の仕事は完了する。
部分探索間の早期キャンセルや学習節の共有は行わない。SAT のモデルは各部分探索の結果から
数値が最小のものを選ぶ。分割なしとモデルが変わることはあるが、SAT / UNSAT の判定は変わらない。
この方式では、分割を増やすことで探索総量も増え得る。

正しさは Python の全割当列挙で確認した。ランダム CNF 48個、生成した3-SAT 32個のほか、
空・矛盾する単位節・伝播の鎖・恒真節・重複リテラル・バックトラックが必要な SAT / UNSAT を含む。
SAT の全モデルを元の節に照合した。C / Bend の1・4スレッドで、モデル・判定・ノード数が一致した。
最上位の32番目のビットと4096節の入力も検証した。
SAT 用9テストを含め、`just test` の全28テストが通った。

計測は Apple M5、10スレッド、32 GiB、macOS 26.6.2、Bend 2.0.34
(`7d24b8d0235cb9781140512c0f163c48ea84a719`)。
C は Apple clang 21 / `-O3 -pthread`。同じ CNF、単位伝播、分岐順、早期終了を使う。
C の節は連続した配列、Bend は読み取り用の immutable な連結構造。
C 版の探索中は malloc/free せず、バッチの入力配列はワーカーのスタックに置く。
Bend のバッチでは各 CNF の割当と解放も時間に含める。

各条件は C 1 → C 10 → Bend 1 → Bend 10 の順に出力を照合し、各モードを3回測る。
以下では最小時間を使い、生ログには3回の時間・中央値・最大RSSも残す。
実行は直列で、UI アプリは実行中。こちらから他のベンチ・ビルドを並行起動していない。
単一 CNF の反復は、その CNF の構築を一度だけ行い、毎回探索し直す。
反復間の解や伝播結果の再利用はしない。
C はプロセスごとに pthread プールを一度作り、各反復の間に barrier を入れる。
分割なしの C はワーカー1個に制限する。Bend のランタイムもプロセス全体でプールを使う。

独立したランダム3-SAT の結果:

| 入力 | C 1 | C 10 | Bend 1 | Bend 10 |
|---|---:|---:|---:|---:|
| 24変数・102節 × 1,024件 | 0.019s | 0.004s | 0.116s | 0.021s |
| 24変数・102節 × 16,384件 | 0.270s | 0.038s | 1.804s | 0.307s |
| 32変数・136節 × 65,536件 | 3.228s | 0.449s | 23.079s | 4.398s |

大きい条件では Bend が1→10スレッドで約5.25倍、C が約7.19倍に伸びた。
C 10 は Bend 10 より約9.79倍速い。中央値も C 10 が0.466s、Bend 10 が4.455sで、大小関係は同じ。
全条件で checksum・ノード数・errors が4モードで一致した。errors は0。
65,536件の総ノード数は4,080,707。これは未割当変数を全列挙する #SAT ではなく、
各 CNF について SAT の最初のモデルで停止する判定問題の計測。

単一 CNF は、30変数・141節の pigeonhole(6,5) を2,048回逐次に解いた。
全条件で UNSAT、同じ深さの4モードでノード数が一致した。

| 初期割当の分割 | C 1 | C 10 | Bend 1 | Bend 10 | 1回の探索ノード |
|---|---:|---:|---:|---:|---:|
| なし | 0.102s | 0.103s | 1.171s | 1.204s | 239 |
| 4通り (depth=2) | 0.099s | 0.069s | 1.198s | 0.903s | 238 |
| 16通り (depth=4) | 0.104s | 0.069s | 1.162s | 0.627s | 246 |
| 256通り (depth=8) | 0.109s | 0.085s | 1.315s | 0.542s | 462 |

分割なしの Bend 1 に対し、256分割の Bend 10 は約2.16倍速かった。
同じ256分割の1→10スレッドでは約2.43倍。
細かく分けるとノード数も増える。C は16分割までで最速となり、256分割では遅くなった。
この小さい CNF の結果を、大きな産業用 SAT インスタンスの性能には一般化しない。

**独立した CNF の束は並列に伸びたが、今回の SAT 実装で C を上回る速度は確認できなかった。**
単一 CNF の分割は効果が小さく、分割の深さと探索総量も比較する必要がある。
C の連続配列と Bend の連結構造ではデータ表現も違うため、差を言語の実行系だけには帰属できない。
速度差の原因を特定するプロファイルは未実施。
