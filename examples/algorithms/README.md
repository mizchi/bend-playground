# Bend に向くアルゴリズムの候補と CPU 実測

従来の実験は、独立した試行を大量に回して和・最大値・小さな集計にまとめる形に偏っていた。
これは GPGPU にも自然な計算の形で、CPU で実行していても題材の偏りは残る。
MCTS の分岐や木の更新は既に含まれるが、非数値の処理と C の並列実装を増やして確かめた。

今回追加したのは、**単一問題の厳密な組合せ探索、可変回数の整数処理、木の構築と書き換え**の3種類。
Apple M5 / 10スレッドで9条件を測り、全条件で C / Bend の1・10スレッドの出力が一致した。
N-Queens と素因数分解は C 並列版が速い。式の木の定数畳み込みは、この入力と実装では Bend 並列版が速かった。

追加で [DPLL SAT ソルバー](sat/README.md) を実装した。DIMACS 入力、単位伝播、モデルの検証に対応し、
独立した CNF のバッチと単一 CNF の初期割当分割をそれぞれ C の逐次・並列版と比較する。
32変数の65,536件で Bend は23.079s → 4.398sに伸びたが、C 10 は0.449sだった。
単一 CNF の初期割当分割は、Bend の分割なしに対して約2.16倍の高速化だった。

候補の条件は、各仕事が自分の状態を持てること、仕事を十分な大きさにまとめられること、
合流が小さな値の集計または独立した結果の連結になること。
下表の「候補」はこの条件からの仮説で、速度を確認済みという意味ではない。

| アルゴリズム・用途 | 並列化する単位と注意点 | 検証状況 |
|---|---|---|
| Monte Carlo 積分・確率推定 | 独立試行の束を分け、和を集計する | π 推定を既存実験で計測。C 対照は1スレッド |
| 焼きなまし・ランダムリスタート | 独立チェーンを分け、最良値を選ぶ | `sim/anneal` を既存 CPU 実験で計測。C 対照は1スレッド |
| 小さな系のシミュレーション | 世界・シナリオを分け、状態をスカラーで持つ | `sim/galton`、`balls_flat` を既存 CPU 実験で計測 |
| N-Queens のビットボード DFS | 最初の数手で部分問題を分け、内部は逐次探索、解数を合計 | **今回追加。C 並列版より約1.41倍遅い** |
| SAT の DPLL、Exact Cover | 独立した部分探索を分ける。共有の学習節や大きい状態のコピーは別評価 | DPLL は CPU 計測済み。今回の実装では C が速い。[SAT の比較](sat/README.md)。Exact Cover は未計測 |
| ナップサック等の branch-and-bound | 上位の部分問題を分け、局所的な上下界で探索する。共有最良値による枝刈り量の差も調べる | 候補、未計測 |
| αβ探索・negamax | 独立局面の束を分ける。1本の木を分割すると枝刈りの効き方が変わる | 候補、未計測。MCTS の既存計測とは別 |
| Pollard ρ 法による素因数分解 | 独立した整数を分け、各整数の反復と GCD は逐次に回す | **今回追加。C 並列版より約2.53倍遅い** |
| AST の定数畳み込み・木の書き換え | 独立した式・関数の木を分け、木の中は逐次に処理する | **今回追加。この C 並列版より約1.36倍速い** |
| 再帰下降パーサー・JSON 検証 | 文書単位で分け、各文書の入力とパーサー状態を専有する | 候補、未計測 |
| NFA による正規表現照合 | 文書・レコード単位で分け、小さな状態集合を専有する | 候補、未計測 |
| ヒープ・優先度キューの操作列 | 独立キューを分ける。C の配列ヒープとも比較する | `examples/ds/map/m2` にソースあり、タイミング未計測 |
| Smith–Waterman 等の配列 DP | 独立した配列・配列ペアを分け、各 DP は逐次に回す。C の SIMD 実装との比較が必要 | 候補、未計測 |
| ブロック単位の LZ77 系圧縮 | ブロック内の辞書・バッファを専有する。出力の連結まで含めて測る | 候補、未計測 |
| 適応的数値積分 | 粗い区間を分け、細かい適応再帰は逐次に回す。仕事量の偏りも調べる | 候補、未計測 |
| BVH を使うレイトレーシング | レイの束を分け、読み取り専用の木を参照する | この比較では未計測。GPU にも自然な題材 |

今回の大きい入力の結果（秒、3回の最短値）:

| アルゴリズム | 規模 | C 1 | C 10 | Bend 1 | Bend 10 | Bend 内の並列化 |
|---|---|---:|---:|---:|---:|---:|
| N-Queens | 16×16、最初の2行で分割 | 4.730 | 0.634 | 6.559 | 0.892 | **7.36倍** |
| Pollard ρ | 2^22 個の小さな半素数 | 1.700 | 0.302 | 4.654 | 0.763 | **6.10倍** |
| AST 定数畳み込み | 2^20 本、各木の深さ9 | 3.908 | 1.212 | 5.858 | 0.894 | **6.55倍** |

同じ入力で3回の中央値を比べても結論は変わらない。

| アルゴリズム | C 10 の中央値 | Bend 10 の中央値 |
|---|---:|---:|
| N-Queens | 0.641s | 0.898s |
| Pollard ρ | 0.303s | 0.786s |
| AST 定数畳み込み | 1.223s | 0.901s |

AST は実行順も入れ替えて追加確認した。C→Bend、Bend→C、C→Bend の3組の中央値は
C 1.241s / Bend 0.895s で、Bend が約1.39倍速かった。
この差の原因を切り分けるプロファイルは未実施。全ての AST 処理で同じ倍率になるとは言えない。

短い条件はプロセス起動の影響が大きいため、速度の判断には大きい条件を使った。
**独立状態と粗い並列化は並列に伸びる条件だが、C に勝つ十分条件にはならない。**
非数値の探索と木の処理でも並列化は効いた。大きな状態を共有するグラフ探索・単一配列のソートなどは、
今回の3本では検証していない。GPU の速度も今回の対象に含めていない。

比較条件と入出力のコントラクト:

- Bend 2.0.34、`7d24b8d0235cb9781140512c0f163c48ea84a719`。Apple M5、性能4 + 効率6コア、32 GiB、macOS 26.6.2。
- C は Apple clang 21、`-std=c11 -O3 -ffp-contract=off -pthread`。同じ探索・生成・変換規則を使う。
- C 並列版は pthread と動的なジョブキュー。N-Queens は1件ずつ、他は16件ずつワーカーに配る。
- Bend は上位の fork 木でジョブを分け、ジョブ内部は逐次に実行する。共有の可変状態を使わない。
- N-Queens は `dep=8`、`size=4..16`。256通りの2行の接頭辞を分け、無効な接頭辞を除く。対称性による探索省略は行わない。
- ρ の入力は1009〜1097の固定16素数から2個選んだ積で、同じ素数の二乗も含む。Floyd の巡回検出を使い、巡回失敗時には多項式の定数を増やして再試行する。一般の大きな整数を対象にした性能ではない。
- AST は定数・変数・加算・乗算の木。定数演算、`x+0`、`x*0`、`x*1` を畳み込む。入力生成、変換、評価、残存ノード数の集計を計測に含める。
- AST の C 版は各ワーカーが1023ノードの配列 arena を再利用し、木を in-place に変換する。ノードごとの malloc/free は使わない。
- AST のソース読込、字句解析、名前解決、型検査、出力のシリアライズは計測に含めない。コンパイラ全体の性能を測ったものではない。
- 出力は `checksum=<U32> detail=<U32> errors=<U32>` の1行。checksum と detail の加算は 2^32 を法とする。
- N-Queens の checksum は厳密な解数、detail は0。ρ の checksum は小さい素因数・大きい素因数・入力位置から求め、detail は反復数。AST の checksum は評価値を入力位置で重み付けした和、detail は変換後のノード数。
- errors は ρ の反復予算を使い切った件数。0以外なら計測を停止する。コンパイルや実行の失敗、出力不一致でも停止する。
- 各条件の出力を1回照合した後、時間を3回測る。実行順は C 1 → C 10 → Bend 1 → Bend 10。プロセス起動を含み、コンパイルを除く。
- 実行は直列。UI アプリは実行中で、こちらから他のベンチ・ビルドを同時起動していない。計測前後に thermal / performance warning は記録されていなかった。

正しさは C twin との一致に加え、独立した基準で確かめた。
N-Queens の小さい規模は n=4 の2通り、n=8 の92通り、n=10 の724通りに一致する。
計測した n=14/15/16 も365596 / 2279184 / 14772512に一致する。[OEIS A000170](https://oeis.org/A000170)
ρ は試し割りで求めた素因数と照合した。計測した全サイズの checksum も、素数表の素数性を独立に確認し、
入力の2素数を並べて求めた期待値に一致した。AST は Python で元の式を評価した値と、抽象評価による残存ノード数を照合した。
AST のオラクル照合には計測と同じ深さ9も含める。`just test` は既存8件・計測用5件・アルゴリズム用6件の全19件が通った。

再現するにはリポジトリのルートで実行する。

```sh
just check-algorithms
just bench-algorithms

# 条件を選び、3回の個別時間・中央値・RSS・環境を JSON に保存する
just bench-algorithms nqueens rho astfold --output build/algorithms/results.json
just bench-algorithms nqueens --case n16
```

[suite.json](suite.json) が対象とサイズを定義する。[生の計測値](results-macos-m5-2026-10-02.json) には
コンパイラ・Bend のコミット、ソースの SHA-256、各実行の時間、最大RSS、追加の実行順確認を保存した。
生成されたバイナリとサイズ変更用のソースコピーは `build/algorithms/` に置く。
計測後にハーネスの CLI 既定値だけを修正しており、計測時と修正後のハッシュを生ログに記録した。

アルゴリズムの参考は、ρ 法の説明と再試行方法がある
[Handbook of Applied Cryptography, Chapter 3, Algorithm 3.9 / Note 3.12](https://cacr.uwaterloo.ca/hac/about/chap3.pdf)、
定数畳み込みの実装例がある [LLVM ConstantFolding](https://llvm.org/doxygen/ConstantFolding_8h_source.html)。
今回の処理系・入力・変換規則はこのリポジトリで定義したもの。
今後の比較対象の幅を考える参考として、[PBBS](https://www.cs.cmu.edu/~pbbs/benchmarks.html) には
ソート・文字列・グラフ等の問題と、逐次・並列の実装が用意されている。
